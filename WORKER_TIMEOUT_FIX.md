# Исправление проблемы с таймаутами изображений

## Проблема

При отключенном VPN изображения не загружаются через Cloudflare Worker, получая ошибку `ERR_TIMED_OUT`. Это происходит потому, что:

1. Cloudflare Worker находится в регионе, где `db.acoustic.ru:3005` недоступен без VPN
2. Worker пытается получить доступ к API, но запрос таймаутит
3. Изображения не загружаются, хотя JSON данные могут загружаться успешно

## Решение

Реализован автоматический fallback механизм:

### 1. Улучшенная обработка ошибок в Worker

Cloudflare Worker теперь:
- Возвращает понятные ошибки при таймаутах
- Логирует проблемы для отладки
- Корректно обрабатывает сетевые ошибки

### 2. Автоматический fallback на клиенте

При ошибке загрузки изображения через Worker:

1. **Первая попытка**: Загрузка через Cloudflare Worker
2. **При таймауте/ошибке**: Автоматическое переключение на прямой URL (`https://db.acoustic.ru:3005`)
3. **При ошибке прямого URL**: Изображение скрывается

### 3. Оптимизация предзагрузки

- Уменьшено количество параллельных загрузок (с 4 до 2 для иконок)
- Добавлен таймаут 8 секунд для определения проблемных изображений
- Автоматический fallback при ошибках предзагрузки

## Как это работает

### В компонентах

```jsx
<img 
  src={getImageUrlWithFallback(imageName)}
  onError={(e) => {
    // Автоматически пробует прямой URL при ошибке
    const fallbackUrl = getImageUrl(imageName, true);
    // ...
  }}
/>
```

### В API сервисе

1. `getImageUrlWithFallback()` - проверяет, был ли Worker неудачен для этого изображения
2. Если да - сразу использует прямой URL
3. Если нет - пробует Worker

## Рекомендации

### Если Worker все еще не работает

1. **Проверьте регион Worker**: 
   - В настройках Cloudflare Worker можно указать регион
   - Выберите регион, где `db.acoustic.ru` доступен

2. **Используйте прямой URL как основной**:
   - Установите `VITE_API_PROXY_URL` пустым
   - Приложение будет использовать прямой URL напрямую

3. **Альтернативный прокси**:
   - Рассмотрите использование другого прокси-сервиса
   - Или разместите Worker в другом регионе

### Проверка работы

1. Откройте DevTools → Network
2. Найдите запрос изображения
3. Проверьте:
   - Первая попытка идет через Worker
   - При ошибке - вторая попытка через прямой URL
   - В консоли должны быть сообщения о fallback
